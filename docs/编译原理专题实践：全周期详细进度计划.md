## 编译原理专题实践：全周期详细进度计划

### 第一阶段：项目启动与架构设计（第 1 周）

**目标**：环境搭建、分工明确、设计 Lex 输入规范。

- **全组共同**：确定目标语言（如 C99 子集）、搭建 Git 仓库、选择开发语言（C++/Java/Python 等）。
- **Lex 负责人**：分析 Lex 输入文件格式（Definitions, Rules, Actions），设计存储 RE（正规式）的数据结构。
- **Yacc 负责人**：研究 Yacc 语法规则格式，设计产生式和非终结符的存储结构。
- **语义/中间代码负责人**：配置 LLVM 或 Soot (Jimple) 环境，跑通一个简单的 "Hello World" 级别的代码生成 Demo。

### 第二阶段：核心算法实现（第 2 - 3 周）

**目标**：完成词法分析与语法分析的核心引擎。

- **Lex 负责人**：
  - 实现 RE -> NFA (Thompson 构造法)。
  - 实现 NFA 的合并（处理多个规则）。
  - 实现 NFA -> DFA (子集构造法) 及 DFA 最小化。
- **Yacc 负责人**：
  - 实现 First 集与 Follow 集的计算。
  - 构建 LR(0) 或 LALR(1) 项目集规范族。
  - 构造 Action 表和 Goto 表。
- **语义/中间代码负责人**：
  - 设计符号表（Symbol Table）结构，支持作用域管理。
  - 定义中间代码的抽象语法树（AST）节点类型。

### 第三阶段：模块集成与初步测试（第 4 - 5 周）

**目标**：实现从源代码到 AST 的完整转化。

- **Lex 负责人**：完成 Scanner 逻辑，能够根据生成的 DFA 对输入流进行切词，并返回 Token 给 Yacc。
- **Yacc 负责人**：完成 Parser 逻辑，驱动状态栈进行移进-归约，并在归约时调用语义动作。
- **语义/中间代码负责人**：编写 AST 构造函数，将其嵌入 Yacc 的归约动作中，实现“边解析边建树”。

### 第四阶段：语义分析与代码生成（第 6 - 7 周）

**目标**：生成可运行的中间代码。

- **Lex & Yacc 负责人**：转为测试与优化。编写复杂的测试用例（如多层循环、递归调用），修复 Parser 的冲突（Shift/Reduce 冲突）。
- **语义/中间代码负责人**：
  - 实现类型检查（Type Checking）。
  - 遍历 AST，调用 LLVM IR 或 Jimple API 生成中间代码（如 `newAddExpr`, `newVirtualInvokeExpr`）。
  - 处理控制流（if/else, while）的 Label 跳转。

### 第五阶段：文档完善与验收准备（第 8 周）

**目标**：完成实验报告，准备答辩。

- **全组共同**：
  - **整理 AI 使用记录**：按照 PPT 要求，记录使用的 AI 工具、提示词（Prompts）以及验证过程。
  - **编写实验报告**：重点描述 Lex/Yacc 的自动化构造过程，而非手写代码。
  - **准备演示**：录制 Demo 视频或准备现场演示。
